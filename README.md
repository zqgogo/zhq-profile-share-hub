# Profile Share Hub

一个面向手机端的轻量 Web 应用，用来生成可分享的资料页，并配套公开访问、聊天、匹配分析、管理后台和 Claw skill 调用能力。

当前支持两种资料类型：

- `简历`
- `相亲交友`

统一后台入口：

- 未设置后台口令时：`/admin`
- 设置了 `ADMIN_TOKEN` 时：`/admin?token=你的后台口令`

Claw skill 当前调用的是本地发布服务：

- 创建：`skills/profile-share-assistant/scripts/publish_profile.js`
- 管理：`skills/profile-share-assistant/scripts/manage_profile.js`

这个项目的核心使用方式是：

- 你在后台创建资料页
- 系统生成 `公开链接` 和 `管理链接`
- 公开链接发给别人看
- 管理链接自己保留，用来上下线、重生成、重置次数、生成访客专属链接

项目正式目录：

`.`

Claw 口令汇总文档：

- [CLAW_USAGE.md](./CLAW_USAGE.md)

## 1. 当前功能

### 公开页能力

- 手机端 Web 适配
- 根据资料类型自动使用不同排版和文案风格
- 支持可选上传图片
- 支持资料查看
- 支持匹配分析
- 支持跳转到独立聊天页
- 支持聊天历史回看
- 支持页面下线后只读

### 管理页能力

- 编辑资料
- 重新生成内容
- 上线 / 下线
- 重置匹配次数和聊天次数
- 生成访客专属链接
- 查看最近匹配和聊天记录

### 统一后台能力

- 统一查看全部资料页
- 查看哪些页面在线 / 下线
- 查看每个页面的剩余次数、访客链接数、互动记录数
- 一键进入公开页、聊天页、单页管理页
- 一键上下线
- 一键重置次数

### 次数控制

默认限制：

- 匹配分析：`3` 次
- 聊天次数：`10` 次

如果使用“访客专属链接”，每个访客链接都有自己独立的：

- 匹配次数
- 聊天次数
- 聊天历史

这比所有人共用一个公开链接更适合实际分享场景。

```bash
cd .
npm start
```

[http://127.0.0.1:8787](http://127.0.0.1:8787)

```bash
cd .
npm run dev
```

说明：

- `npm start`：普通启动

```bash
cd .
./scripts/start_service.sh
```

- 如果传了参数，就把它写入 `PUBLIC_BASE_URL`

## 4. 使用流程

### 4.1 创建资料页

1. 打开首页。
2. 选择资料类型：
   - `简历`
   - `相亲交友`
3. 输入：
   - 姓名或称呼
   - 页面标题
   - 强调重点
   - 原始输入
4. 如有需要，可开启图片上传。
5. 点击“生成资料页面”。
6. 系统返回：
   - `公开链接`
   - `管理链接`

### 4.2 分享给别人

- 把 `公开链接` 发给别人
- 对方可以：
  - 查看资料
  - 输入自己的资料进行匹配分析
  - 进入聊天页进一步了解

注意：

- 公开页的视角是“访客视角”
- 例如相亲交友页里输入框提示的是“输入你的资料”
- 简历页里输入框提示的是“输入你的招聘需求 / 岗位 JD”

### 4.3 你自己管理页面

保留 `管理链接`，后续可以做这些操作：

- 修改资料内容
- 重新生成页面
- 上线 / 下线
- 重置匹配次数
- 重置聊天次数
- 生成访客专属链接

## 5. 资料类型说明

### 5.1 简历

适合：

- 求职
- 招聘沟通
- 岗位匹配

公开页更偏向这些内容：

- 工作经历
- 技能栈
- 项目亮点
- 岗位相关性

访客输入内容通常是：

- 招聘需求
- 岗位 JD
- 关注的工作能力维度

### 5.2 相亲交友

适合：

- 相亲
- 轻社交认识
- 微信转发给别人先看资料

公开页更偏向这些内容：

- 基本信息
- 性格与相处风格
- 兴趣爱好
- 关系期待

访客输入内容通常是：

- 自己的资料
- 自己的性格、兴趣、经历
- 想重点了解的匹配方向

系统会给出多维关系分析，并可轻量加入 `生肖参考`。

说明：

- `生肖参考` 是辅助维度，不是唯一判断标准
- 目前不是严格意义上的完整八字测算
- 如果后续你想增强玄学部分，建议补充出生年月日时和出生地

## 6. 匹配分析和聊天机制

### 6.1 匹配分析

默认每个资料页有 `3` 次匹配机会。

用途：

- 简历：分析候选人与岗位 / 招聘需求的匹配度
- 相亲交友：分析来访者与当前资料页的关系匹配度

输出通常包括：

- 一句话总结
- 多个分析维度
- 若干条具体结论
- 一条风险提醒或注意点

### 6.2 聊天

默认每个资料页有 `10` 次聊天机会。

特点：

- 独立聊天页
- 可以回看聊天历史
- 页面显示剩余聊天次数

当前设计目标是：

- 控制 token 消耗
- 防止公开页面被无限滥用

### 6.3 访客专属链接

如果你不希望所有人共用同一套次数和聊天记录，可以在管理页里生成“访客专属链接”。

生成后：

- 每个访客链接都有单独次数
- 每个访客链接有自己的聊天历史
- 更适合一对一分享

这个功能建议作为默认分享方式使用。

## 8. 配置说明

### 8.1 配置文件位置

当前项目支持两种配置来源：

1. 项目根目录下的 `.env`
2. 系统环境变量

优先级：

- 如果系统环境变量已存在，会优先生效
- `.env` 只会给“当前还没设置的变量”补默认值

也就是说，如果你已经在 shell 里 `export PUBLIC_BASE_URL=...`，那么 `.env` 里的同名配置不会覆盖它。

### 8.2 如何创建配置文件

```bash
cd .
cp .env.example .env
```

然后编辑 `.env`。

示例：

```env
PORT=8787
HOST=127.0.0.1
BASE_URL=http://127.0.0.1:8787
PUBLIC_BASE_URL=https://你的公网域名
AI_API_URL=https://你的模型接口地址/v1/chat/completions
AI_API_KEY=你的密钥
AI_MODEL=你的模型名
AI_EXTRA_HEADERS=
```

### 8.3 每个配置项的作用

#### `PORT`

服务监听端口。

例如：

- `8787`
- `3000`

#### `HOST`

服务监听地址。

常见值：

- `127.0.0.1`：只允许本机访问
- `0.0.0.0`：允许局域网或外部代理访问

#### `BASE_URL`

服务内部使用的基础地址，主要用于服务端构造 URL 和处理请求时的默认基准地址。

本地开发一般保持：

`http://127.0.0.1:8787`

#### `PUBLIC_BASE_URL`

最重要的配置之一。

作用：

- 决定系统返回给用户的“公开链接 / 管理链接 / 聊天链接”长什么样

如果你在本地看效果：

`PUBLIC_BASE_URL=http://127.0.0.1:8787`

如果你用了内网穿透或云服务器：

`PUBLIC_BASE_URL=https://你的公网域名`

不改这个的话，即使服务已经公网可访问，生成出来的链接也可能还是本地地址。

#### `ADMIN_TOKEN`

统一后台口令，也是后台登录密码。

作用：

- 给 `/admin` 总后台加一层简单保护
- 配置后访问方式变成：
  - `/admin?token=你的后台口令`

如果不填：

- 后台默认可直接访问
- 更适合本地开发
- 不建议在公网长期裸露

#### `AI_API_URL`

AI 模型接口地址。

要求：

- 兼容 OpenAI Chat Completions 风格

#### `AI_API_KEY`

调用模型接口所需的密钥。

#### `AI_MODEL`

模型名称。

#### `AI_EXTRA_HEADERS`

额外请求头。

格式：

`Header-A:value-a,Header-B:value-b`

适合某些代理服务、网关鉴权或供应商自定义头。

#### `OPENCLAW_CONFIG_PATH`

可选。

默认值：

`~/.openclaw/openclaw.json`

作用：

- 当你没有显式配置 `AI_API_URL / AI_API_KEY / AI_MODEL` 时
- 服务会尝试从这个文件里读取 OpenClaw 已有的模型配置并复用

如果你将来换机器或换账号，可以通过这个变量指定新的 OpenClaw 配置文件位置。

### 8.4 AI 配置回退逻辑

当前逻辑是：

1. 优先使用环境变量 / `.env`
2. 如果没配，再尝试读取 OpenClaw 配置
3. 如果两边都没有，就使用本地 fallback 文案逻辑

也就是说：

- 不配 AI 也能用
- 只是文案和分析会更保守

### 9.2 临时外网演示

本项目已经切换为仅推荐 Render 免费部署，不再提供 Cloudflare tunnel / workers.dev 方案。

### 9.3 上云部署时建议

建议至少做这几件事：

- 把 `HOST` 改成 `0.0.0.0`
- 正确设置 `PUBLIC_BASE_URL`
- 保留 `data/profiles` 目录
- 使用进程守护工具管理服务
- 配反向代理和 HTTPS

如果后面你要正式上云，这个项目已经预留好了配置点，不需要大改结构。

### 9.4 免费服务器（Render）快速部署

如果你想要一个真正“固定可访问”的免费地址（不依赖本地隧道在线），可以直接用 Render 免费 Web Service。

本仓库已提供部署文件：

- `render.yaml`

部署步骤：

1. 把项目推到 GitHub
2. 打开 Render，选择 **New + -> Blueprint**
3. 选择你的仓库，Render 会自动识别 `render.yaml`
4. 首次部署完成后会得到固定地址：`https://<service-name>.onrender.com`

说明：

- Render 免费实例会在空闲一段时间后休眠，首次访问会慢几秒到几十秒
- 公开域名是固定的，适合手机直接访问
- 项目已支持自动读取 Render 的 `RENDER_EXTERNAL_URL`，通常不需要手动改 `BASE_URL`

## 10. 管理页说明

管理页 URL 形式类似：

`/manage/{id}?token=xxxx`

这个链接同时包含：

- 资料页 id
- 私有管理 token

所以：

- 不要把它发给别人
- 丢了就等于失去该页面的完整管理能力

管理页里可以做的操作包括：

- 保存资料修改
- 重新生成
- 下线
- 重新上线
- 重置次数
- 生成访客专属链接

## 10.5 统一后台说明

后台入口：

- 本地未设口令时：
  - [http://127.0.0.1:8787/admin](http://127.0.0.1:8787/admin)
- 配置了 `ADMIN_TOKEN` 时：
  - `http://127.0.0.1:8787/admin?token=你的后台口令`

后台适合开发者自己用来总览和管理，不适合发给访客。

当前后台可以：

- 查看所有资料页
- 按类型和状态筛选
- 看匹配 / 聊天剩余次数
- 看访客专属链接数量
- 看匹配 / 聊天记录数
- 一键跳转单页管理
- 一键上下线
- 一键恢复默认次数

后台登录方式：

- 如果没配置 `ADMIN_TOKEN`，后台直接可访问
- 如果配置了 `ADMIN_TOKEN`，访问 `/admin` 会先进入登录页
- 登录成功后会写入后台会话 cookie
- 也保留 `/admin?token=...` 作为直达兜底方式

## 15. 常见问题

### 15.1 为什么生成出来的还是本地地址？

因为 `PUBLIC_BASE_URL` 没改。

把它改成你的公网地址后重新启动服务即可。

### 15.2 为什么外网能打开，但生成链接还是 `127.0.0.1`？

同样是 `PUBLIC_BASE_URL` 没配对。

服务可访问地址和“系统生成给用户的地址”是两回事。

### 15.3 为什么页面可以看，但不能匹配或聊天？

可能原因：

- 页面已下线
- 对应次数已用完
- 当前访问的是某个访客专属链接，而该链接自己的次数已耗尽

### 15.4 为什么 AI 没生效？

检查：

- `AI_API_URL`
- `AI_API_KEY`
- `AI_MODEL`

如果你没配这些，再检查：

- `OPENCLAW_CONFIG_PATH` 指向的 OpenClaw 配置是否存在

### 15.5 为什么我改了 `.env` 没生效？

改完 `.env` 后需要重新启动服务。

### 15.6 迁移服务器时最关键要带什么？

至少保留：

- 项目代码
- `.env`
- `data/profiles`

### 15.7 Claw 里怎么调用这个项目？

当前方式是：

1. 保证本地服务已经启动。
2. 让 Claw 命中 `profile-share-assistant` 这个 skill。
3. skill 会调用本地脚本，再调用本地接口。

你在 Claw / 微信里可以直接说：

- `帮我生成一个简历页，信息如下：...`
- `帮我生成一个相亲交友资料页，信息如下：...`
- `根据这个管理链接把页面下线`
- `根据这个管理链接把页面重新上线`
- `根据这个管理链接重置聊天和匹配次数`

如果要手工指定接口地址，可改：

- `PROFILE_PUBLISHER_URL`
- `PROFILE_PUBLISHER_BASE_URL`

### 15.8 现在做了哪些安全加固？

当前已经加了这些：

- 后台登录口令
- 后台登录态 cookie
- 后台接口鉴权
- 安全响应头
- 请求体大小限制
- 基础频率限制
- 公开页和后台页隔离

说明：

- 这个项目目前没有 SQL 数据库，所以不存在传统 SQL 注入点
- 数据存储是本地 JSON 文件
- 主要风险点在于后台暴露、管理链接泄露、以及公网暴露后的滥用

---

## 16. 推荐的后续优化方向

当前已经能跑完整链路，后续更适合继续补这些：

- UI 继续精修
- 图片改成真实文件存储或对象存储
- 管理页增加删除资料页能力
- 支持更多访客链接标签和批量管理
- 相亲交友页补更多“轻量玄学”维度
- 云服务器部署脚本
- 登录或基础权限体系
- 数据备份和恢复方案
